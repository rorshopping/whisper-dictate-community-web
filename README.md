# Whisper Dictate Community Edition site

This is a separate, static landing page for the free community edition. It is
intentionally independent from the paid site in `website/`: no payment code,
payment configuration, analytics, cookies, API routes, or secrets belong here.

The page makes a deliberately narrow promise:

- the source repository is the reference for the software and its current
  license;
- model weights are not bundled with the application or this site;
- the documented model is acquired from Hugging Face on first use, and the
  model publisher's license applies;
- after the model is cached, recording and transcription run locally.

No verified community artifact is advertised yet. The download controls are
disabled on purpose until `releases.json` contains canonical URLs and real
SHA-256 checksums.

## Files

- `index.html` — accessible landing page and download information.
- `styles.css` — independent responsive visual theme.
- `app.js` — fetches and renders the same-origin release manifest without a
  framework or third-party script.
- `releases.json` — the generated/configurable release manifest and model link
  index. It is a data file, not a secret.
- `privacy.html` and `licenses.html` — privacy and license/model notices.
- `vercel.json` — Vercel routing plus security headers.
- `scripts/validate_site.py` — offline HTML, link, manifest, and security
  validation.

## Local preview and validation

From the repository root, run:

```bash
python scripts/validate_site.py
python -m unittest discover -s tests -p 'test_*.py'
python -m http.server 8000 --directory .
```

Open `http://127.0.0.1:8000/` for a local preview. The validator and its smoke
test use only the Python standard library and never make a network request.
They are safe to run before and after changing the manifest.

## Vercel deployment

This directory is a static site, so Vercel does not need a build command,
framework preset, serverless function, or package installation.

1. Create or select a Vercel project for this repository.
2. Keep the project **Root Directory** as `.` (the repository is the site).
3. Keep `vercel.json`; it enables clean URLs and applies the security headers.
4. Preview the project and run the offline validator before promoting a
   preview.
5. Do not add environment variables, API routes, or private release tokens to
   this directory. A public static download URL belongs in `releases.json`, not
   in a secret.

## Replacing the safe placeholders after a release

Only update the manifest after the release owner has verified the artifacts:

1. Set `release.status` to `published`.
2. Set `release.version` and `release.published_at` to the actual release values.
3. Set `release.release_page` to the canonical public release page, if there is
   one. It must be an `https` URL; do not use a guessed or tracking redirect.
4. For each artifact that is actually available, set `filename`, the final
   public `url`, `sha256`, and `size_bytes`. Leave unavailable artifacts as
   `null`; the page will keep them disabled.
5. Confirm that portable ZIPs and installers are clearly identified, and that
   the artifact is built for the declared architecture.
6. Recompute checksums from the exact published bytes. Never put a checksum
   copied from another build in the manifest.
7. Run `python scripts/validate_site.py` and inspect the site
   locally before publishing a Vercel deployment.

The manifest can be generated by a release job, but the checked-in file is the
source consumed by the browser. Keep the structure stable so a generator can
replace values without changing the page. The validator rejects non-HTTPS or
placeholder-looking download URLs and requires a 64-character hexadecimal
SHA-256 whenever an artifact is enabled.
